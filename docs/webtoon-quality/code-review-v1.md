# 3인 코드리뷰 및 개선 결과

2026-10-01 / 기반 커밋: 03c7705 / 개발 브랜치: codex/us-webtoon-quality-v1

실제 인간 전문가 회의가 아니라 독립된 리뷰 에이전트 3명이 품질·카논, 발행, 테스트·예산 관점을 검토했다. 시작 시 존재하던 미커밋 안전성 변경을 보존하고 함께 검토했다. 운영 DB, 유료 이미지 생성, SNS 전송은 수행하지 않았다.

## 확인한 결함과 개선

| 검토 영역 | 문제 | 최종 개선 |
|---|---|---|
| 최종 품질 게이트 | 해시가 일치해도 원천 계약 누락·무효 입력을 승인할 여지 | 필수 계약과 근거·주장·서사·REF를 발행 직전 재검증 |

| 모바일 합성 | 사각형 오른쪽·하단 경계에 보호 픽셀 1px 덮어쓰기 | PIL 포함 경계와 사각형 계약 정렬 |
| 서사 기한 | 과거·당일 날짜로 회수 연기를 승인 | 에피소드 거래일 이후 기한만 허용 |

| 면책 | 긴 TG 캡션 절단으로 면책 삭제, X 청크 수에 따라 최종 캡션 누락 | TG 길이 내 면책 보존, X 1~10장 마지막 캡션 보존 |
| 영상 재발행 | video-only 성공 후 중복 방어 정보 없음 | 성공 후에도 HOLD 유지하여 자동 재전송 차단 |
| 추가 영상 실패 | 영상 실패·불명확 응답을 전체 성공으로 처리 | 이미지 이력 기록 후 영상 대사 HOLD, 오류 반환 |

## 검증

리뷰 시작 시 작업 상태의 전체 테스트는 1,069개 통과했다. 이번 3인 리뷰에서 34개 회귀 테스트를 추가했다(품질 기한 4, 파일럿 14, 발행 16). 기존 미커밋 변경의 회귀 테스트도 최종 전체 검증에 포함했다.

최종 전체 테스트는 Python 3.11.16에서 **1,103개 모두 통과(121.36초)**했다. Ruff(`--line-length=100`)와 `git diff --check`도 통과했다. 최초 구현 1,014개 대비 89개가 늘었으며, 그중 이번 3인 리뷰에서 추가한 테스트는 34개다.

```bash
../icg-py311/bin/python -m pytest tests -q
../icg-py311/bin/ruff check . --line-length=100
git diff --check
```

## 운영 제한과 대사

- `PUBLISH_HOLD:`는 기존 error_message 컬럼을 사용하는 보수적 잠금이다. 동일 row의 이전 status/error_message를 조건으로 갱신하고, 토큰이 일치하는 경우만 해제한다. 테스트는 모의 조건부 DB를 사용하며 실제 PostgreSQL/RLS/운영 권한에서의 검증은 수행하지 않았다.
- 부분 성공·타임아웃·응답 ID 누락·이력 저장 실패 후 자동 재전송하지 않는다. 운영자는 X 스레드와 Telegram 채널의 실제 게시물을 확인해 대사하고, 누락분 처리와 이력 정합성을 확인한 후 보류를 해제해야 한다. FORCE_REPUBLISH도 미해결 HOLD를 우회하지 않는다.
- video-only는 성공하더라도 전용 파트 이력이 없어 HOLD를 유지한다. 보류를 해제한 뒤 재실행하면 다시 전송될 수 있다. 영상 파트별 영속 이력과 공급자 대사 어댑터가 후속 과제다.
- SQLite 품질 트랙은 단일 호스트 모의 파일럿이며 live 발행을 차단한다. 동시 생성·발행 전체를 분산 트랜잭션으로 보장하지 않는다.
- 실제 그림의 손·소품·방향·동작, 시장 근거의 진실성, 계산 엔진의 실제 결과, 사람 평가, 승인자 인증, 12편 파일럿 품질은 이 코드리뷰나 단위테스트로 증명되지 않는다.
- 원격 push, PR 생성, merge, 운영 반영은 이번 작업에 포함하지 않았다.
