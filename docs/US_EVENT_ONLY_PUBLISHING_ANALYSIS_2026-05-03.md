# 미장(미국 시장) 중심 이벤트-드리븐 발행 전환 분석 (2026-05-03)

## 배경
- 현재 파이프라인은 일일 실행 후 `episode_assets`가 준비되면 발행 단계(`scripts/run_publish.py`)에서 채널 기준으로 그대로 발행됩니다.
- 이 방식은 `NORMAL`/`INTEL`처럼 저강도 이벤트에서도 발행이 발생할 수 있어, 스토리 임팩트가 약해지는 문제가 있습니다.

## 문제 정의
- 독자 관점: “오늘 왜 이 에피소드를 봐야 하는가?” 명확성이 약해짐.
- 운영 관점: 고강도 이벤트와 저강도 이벤트가 같은 빈도로 노출되어 브랜드 포지셔닝이 흐려짐.
- 데이터 관점: 발행 수는 늘지만, 회차별 전환율/완독률 분산이 커질 가능성.

## 권장 운영 원칙
1. **자동 발행은 메이저 이벤트 한정**
   - 기본 자동 발행 허용 타입: `BATTLE`, `SHOCK`, `AFTERMATH`
   - 확장 허용(시즌 운영 시): `EMERGENCE`, `SEASON_FINALE`, `BATTLE_PLUS_FORM2`, `BATTLE_PLUS_FORM3`
2. **비-메이저 이벤트는 큐에 적재만 하고 발행 스킵**
   - `NORMAL`, `INTEL`, `TACTICAL`, `STALEMATE` 등은 보류
3. **예외 수동 발행 루트 유지**
   - 특별 기획/브랜드 협업 등은 환경변수로 강제 발행

## 이번 반영 사항
- `scripts/run_publish.py`에 메이저 이벤트 게이트를 추가했습니다.
- 기본값: 비-메이저 이벤트는 STEP 8에서 발행을 스킵하고 종료.
- 예외: `PUBLISH_NON_MAJOR=true` 설정 시 기존처럼 발행 가능.

## 기대 효과
- 발행 빈도보다 **서사 밀도** 중심 운영으로 전환.
- “굵직한 사건 발생 시 발행”이라는 채널 기대치 정렬.
- 장기적으로 회차당 반응률(저장/공유/재방문) 개선 가능.
