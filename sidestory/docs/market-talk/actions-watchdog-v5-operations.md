# Actions watchdog v5 development and deployment guide

Status: development branch; not deployed. Supabase remains the market/content/delivery/cost database.
No production migration, cron mutation, paid generation, Facebook POST or main merge was performed by this change.

## Changes
- GitHub normal schedule calls one reusable worker; no external dispatch PAT.
- New watchdog runs on primary completion (including success) and offset schedules.
- A read-only planner inspects DB receipts; no-draft/no-send can run for the first time, existing drafts resume.
- PUBLISHED receipts are verified by exact post_id; SENDING/UNKNOWN and ambiguous model attempts never automatically replay.
- DB v5 owns an immutable afternoon due time, 18:00 normal cutoff, 23:30 same-day recovery cutoff.
- Durable leases and total-three execution cap cover normal/recovery requests. Retry cooldown is 10/30 minutes.
- Model cost keys are unchanged; generation/review results cannot be regenerated by changing run IDs.
- Three scheduler jobs and dispatcher functions are retired by an explicit deployment migration; logs retained.
- Existing v3/v4 functions and old slots remain intact. Policy rows are NOT automatically activated for v5.

## Deployment prerequisites
1. Review this PR and pass Python, embedded PostgreSQL, real independent-connection PostgreSQL and Actions lint CI.
2. Confirm no in-flight dispatcher request or live sender; preserve unknown reservations.
3. Apply additive actions_watchdog_v5 migration and scheduler-retirement migration in a controlled deployment.
4. Confirm only icg_talk_dispatch / cutoff / reconcile jobs were removed; other cron and extensions remain.
5. Set the chosen Page's policy_version=5 and effective_from to the next business day. Keep prior slots immutable.
6. Keep existing SCHEDULE/AUTO/LIVE flags and credentials; enable WATCHDOG_AUTO_RECOVERY only after read-only checks.
   Exact variable: MARKET_TALK_WATCHDOG_AUTO_RECOVERY_ENABLED=true.
7. Verify a current business-day slot and exact PUBLISHED_VERIFIED receipt. Do not backdate or extend v4 content.
8. The unused Vault dispatch PAT is not deleted automatically; check other uses before removing/revoking it.

The watchdog plan job always runs independently of the old WATCH_ENABLED variable. With auto recovery disabled it only reports plans.
Recovery also respects SCHEDULE/AUTO/LIVE and DB pause. Old manual operator stages remain available.
A dry executor invocation only reads a plan; unlike legacy automate it cannot incur model cost.
Known provider rejections remain conservative holds. There is no speculative HTTP-error POST allowlist.

## Limits
GitHub can delay or omit scheduled events; two GitHub workflows are not independent infrastructure.
The morning audit reports the previous completed business day without publishing it.
An exact post ID can be verified after expiry; missing/ambiguous post IDs require operator reconciliation.
Manual publish by revision is intentionally rejected by the v5 executor; daily stored drafts are recovered through the shared worker.
Image Sidestory unknown-cost holds are not automatically released by this watchdog.
